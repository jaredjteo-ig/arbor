## Red-team gaps fixed in this round

### Gap A — `get_managed_employee_ids` returned terminated reports

**Problem.** Helper returned ALL direct reports regardless of
`is_active` / `confirmation_status`. The team dashboard would show
ex-employees forever; an HR-deactivated employee would still appear
on their old manager's queue.

**Counter-argument considered.** Off-boarding workflows (final
claim approval, exit-interview trigger) need access to recent
ex-reports for a window. A flat "filter terminated" would break
those.

**Resolution.** Added `active_only=False` (default) flag to
`get_managed_employee_ids`. Callers explicitly opt-in to the
current-roster view by passing `active_only=True`. The team
dashboard (P4-MG-3) should pass True; the approval endpoints
(P4-MG-2) default to False.

Test: `test_active_only_excludes_terminated_reports` — pins both
`is_active=False` AND `confirmation_status='terminated'`
filtering.

### Gap B — Self-referencing `reporting_manager_id` would let a manager approve their own actions

**Problem.** If HR mis-set an employee's `reporting_manager_id`
to their own employee id (data-integrity bug), the helper would
return `{self_id}` in their managed set. `is_manager_of(self,
self_id)` would be True. Combined with P4-MG-2's team-approval
endpoints, a self-managing employee could approve their own
leave / claims.

**Resolution.** Added a defensive skip when `emp_id == my_emp_id`,
logged as a WARNING so HR sees the data bug. Self can never be in
their own managed set.

Tests:

- `test_self_referencing_manager_id_does_not_include_self`
- `test_is_manager_of_rejects_self_via_self_referencing_bug`

### Gap C — Security model wasn't documented

**Problem.** The module didn't state its assumptions about
JWT revocation. A reader could mistakenly believe `manager_scope`
is sufficient to gate a terminated manager.

**Resolution.** Added a "## Security model" section to the module
docstring stating:

1. JWT revocation on termination is the auth layer's job — this
   helper trusts it.
2. Helper returns ALL reports by default; callers filter for
   active-only.
3. Cross-tenant isolation relies on the auth middleware matching
   JWT `company_id` to the resource `company_id`.
